# 拟境 · nijing

> 世界书驱动的沉浸式情境推演引擎

把自己放进一个世界，做一个行动，看这个世界如何回应。

不是数值游戏 —— 没有血条、金币和属性面板。全屏是长篇小说的阅读质感，
每一幕由你自己配置的大模型实时生成，结尾给出几个可选行动，也可以直接写下你自己的。

**应用本身不内置任何剧本。** 你演谁、身处什么时代、用什么文风，全部由你写的「世界书」决定。
历史正剧、架空江湖、近未来都市 —— 同一套引擎，换一本书就是另一个世界。

## 主题

四套皮肤，都走「低饱和、无题材暗示」的路子 —— 换一本书不用换皮肤。

| 名称 | 定位 |
|---|---|
| **拟境**（默认） | 冷调深墨 + 雾蓝强调色。为沉浸式推演设计，长时间阅读不累眼 |
| **时代报章** | 暖纸 + 砖红，旧报纸质感 |
| **暗夜墨石** | 暖黑 + 橘调，夜读护眼 |
| **素雅宣纸** | 亮白纸面，典雅白描 |

阅读页用的不是 Material 语义色，而是一套**阅读面专用色板**
（`ReadingPalette`：页面底色 / 正文墨色 / 极淡分隔线 / 幕首标记色 / 选项卡底色）——
所以每套皮肤的读感是单独调过的，不是简单换个 `primary` 就完事。

在「我的 → 阅读设置」里切换。切换会立即落盘，不会因为退出应用而丢。

阅读设置里还有：字号、行距、**段首缩进**（顶格 / 一格 / 两格）、
**段间距**（紧凑 / 适中 / 宽松）、**打开时跳到最新一幕**（从首页「继续进入」
直接落在最新进度）、顶栏自动隐藏。

缩进用的是**全角空格**（U+3000）而不是几个半角空格 —— 中文字体下只有全角空格
才等于一个汉字的宽度。分段同时认 `\n` 与 `\n\n`：模型输出的换行数并不稳定。

## 快速开始

1. 装好 App，首次打开会引导你配置模型接口
2. 设置 → 选服务商（默认阿里云百炼），填 API Key，点「测试连接」
   - 默认模型 `qwen3.8-flash`，便宜、快
3. 「**世界**」标签 → 「创建世界」（快速创建 / 手动编写），或「导入」
4. 「**继续**」标签 → 「开始一段新的推演」→ 选一个世界 → 进入

底部三个入口：**世界**（我创造什么）· **继续**（我正在经历什么）· **我的**（设置）。

### 阅读时的操作

推演页是沉浸式的，没有常驻的按钮：

| 操作 | 效果 |
|---|---|
| 单击屏幕 | 唤出/隐藏顶栏（已显示时再次单击即刻隐藏，无需等 3 秒；3 秒无操作自动淡出） |
| 顶栏目录 | 一键展开全书幕次列表并平滑跳转 |
| 推演思考 | 查看当前幕模型的推理思考链（仅当模型输出包含思考时可见） |
| 更多菜单 | 导出 Markdown / TXT、查看时空分岔树、切换世界线、就地微调错字 |
| 主宰模式切换 | 自由输入栏左侧星芒/闪电图标随时切换「主宰模式」（高亮金色），当前意志即刻成为不可撼动的世界铁律 |
| 长按并拖动 | 选中文字，松开后可复制 |
| 从屏幕边缘上滑 | 临时唤出系统状态栏，几秒后自动缩回 |

「我的」里三个设置入口是**各自独立的页面**：模型设置 / 阅读设置 / 推演参数，
点哪个就只显示哪一块，不会三块内容混在一页。

### 世界书字段

| 字段 | 必填 | 说明 |
|---|---|---|
| `name` | ✅ | 世界书名 |
| `era` | | 时代与时间跨度 |
| `worldview` | ✅ | 世界观与背景设定 —— 模型据此推演 |
| `playerRole` | ✅ | 你扮演的人物：身份、职务、年龄、性格、立场 |
| `playerGoal` | | 玩家目标：这一局你想做什么 |
| `narrativeStyle` | | 叙事文风 |
| `extraRules` | | 世界规则与禁忌 |
| `keyCharacters` | | 关键人物（一行一条，可空） |
| `keyFactions` | | 关键势力（一行一条，可空） |
| `keyLocations` | | 关键地点（一行一条，可空） |
| `stateDimensions` | | 状态维度模板：告诉模型「当前世界状态」该盯住什么 |
| `openingScene` | | 开篇场景。填了就由你掌控开场，不走模型 |
| `openingChoices` | | 开篇分支（一行一条） |

人物、势力、地点**允许为空** —— 不强迫你为了开始一局填一堆字段。

### 导入 / 导出

在世界列表点「导入」，支持两种输入：

- **JSON**：完整字段。也兼容常见别名（`title`→name、`setting`/`world`→worldview、
  `role`/`character`→playerRole、`style`/`tone`→narrativeStyle、
  `rules`→extraRules、`opening`/`intro`→openingScene、`choices`→openingChoices）
- **纯文本**：整段当作「世界观设定」，其余字段留空待补

长按任意世界书 → 「导出 JSON 到剪贴板」，可直接分享给别人导入。

`worldbooks/` 目录里放了一份示例世界书，复制内容即可导入。

## 世界状态 vs 编年史

这两块都进 system prompt，但职责**严格区分** —— 混了就会互相矛盾：

| | 世界状态 | 编年史 |
|---|---|---|
| 体裁 | 结构化条目 | 散文叙事 |
| 回答 | 此刻是什么状态 | 过去发生过什么 |
| 时态 | 只写当下 | 只用过去时 |
| 体积 | 有硬上限 | 会累积增长 |

判定规则：一条信息，**回滚到第 5 幕后就不成立了** → 归世界状态；
**永远成立** → 归编年史。

模型每幕只在 `<state>` 块里提出状态变化，**合并、校验、截断全部由应用负责** ——
不让模型每幕凭空重写整个世界。上限用总字符预算 + 宽松条数
（事实 ≤12 条、关系 ≤12 条、事件 ≤8 条、单条 ≤120 字），
而不是「每类 5 条 / 每条 40 字」那种硬截断。

## 自己构建

```bash
flutter pub get
flutter build apk --release --target-platform android-arm64
```

> ⚠️ `--target-platform android-arm64` **必须显式指定**。
> Flutter 的 Gradle 插件会绕过 `android` 里的 `ndk.abiFilters`，
> 只用 abiFilters 的话三个 ABI 全都会打进包里（实测 51 MB vs 18.8 MB）。

### CI

GitHub Actions（`.github/workflows/android.yml`）分两级：

| 触发 | 行为 |
|---|---|
| 推 `main` / 手动 | **只构建**，上传 Artifact，**不发版** |
| 推 `v*` 标签 | 构建 + **发布 Release**（这一步才算"发包"） |

需要配置仓库 Secret `TEST_KEYSTORE_BASE64`（固定签名密钥的 base64）。
没配会退回 debug 签名 —— 那样每个包签名不同，无法覆盖安装。

### 图标

`assets/icon/` 下两张 PNG 是图标源文件，改设计后重跑生成脚本再执行
`flutter pub run flutter_launcher_icons` 即可。

## 一本书一局

进入一个世界时，如果这本书**已经有存档就接着玩**，没有才新建 ——
而不是每次都开一条新的。所以「最近推演」里一本书只会出现一条。
想重开走世界书长按菜单里的「重新开始一局」（会清空当前进度，带确认）。

## 世界线

在某一幕发现走错了，不用「回滚」把后面的剧情销毁 —— 从那一幕**分岔**：

```
主线        第1幕 ── 第2幕 ── 第3幕 ── 第4幕      ← 原样保留
                    │
世界线 2             └── 第2幕' ── 第3幕'          ← 重新做选择
```

- 分岔点之前的剧情保留，从分岔点**重新做选择**
- **原来的世界线完全不动**，连同后面所有幕一起留着
- 阅读页 →「世界线」里可以查看全部、随时切换、重命名、删除
- 每条线**自带** `history` / `chronicle` / `worldState` 三件套，
  所以进度与选择记录天然互不干扰

顶栏第二行会显示当前所在的世界线名（只有一条线时不显示）。

> 早先的「回滚」是**单向销毁**：把后面的幕丢掉，只留一个会被下次覆盖、
> 而且没有任何入口能再打开的备份槽。世界线分支取代了它 ——
> 保留并新增，而不是销毁。

## 测试

```bash
flutter test
```

113 项单元测试，覆盖最容易出隐蔽 bug 的地方：

- **主宰模式与天道敕令** —— 主宰状态下的事实一致性保障、短词条防逆向吞并、正文模板标识与 Markdown 前缀智能清洗、字数下限强硬约束
- **深度思考（Thinking）与流式封装** —— enableThinking 配置序列化、Qwen/百炼等模型思考参数动态注入、reasoning_content 思考流无缝转化
- **世界线分岔与切换** —— 分岔后原线是否完全不动、新线是否继承到分岔点、
  两条线是否互不干扰、切换后四件套是否跟着换、在分岔点重生成时状态是否
  退回 `baseState` 而不是被清空
- **快照一致性与错字微调** —— `history` · `chronicle` · `worldState`
  三者是否始终落在同一个时间点；就地修改错字后历史快照与三位一体不变量完好；旧存档缺快照时能否自愈
- **世界状态的解析、合并与截断** —— 含畸形输入不抛异常、关系走增量、总预算兜底
- **模型输出解析、思维链隔离与正文排版** —— `<think>` 与 `<thought>` 思维链抽取与隔离、
  流式未闭合思考标签隐藏、10 类畸形标签写法、模板占位文字过滤、正文分段（`\n` / `\n\n` / `\r\n`）
- **故事排版导出与常亮配置** —— Markdown 与纯文本双格式小说级排版导出校验、阅读防熄屏配置与安全调用

### 一个踩过的坑：模型会照抄提示词里的模板

早先内核提示词里写的是可直接照抄的示例行：

```
<choices>
第一条可供主角决断的具体行动（一句话，30~60 字）
第二条可供主角决断的具体行动
第三条（可选）
</choices>
```

结果模型把这四行当成「格式的一部分」原样抄进了输出 —— 界面上出现了
「第一条可供主角决断的具体行动（一句话，30~60 字）」混在真实选项里，
正文里也混进了「（正文：约 500 字的白描叙事）」。

修法是两层：内核改成**空骨架 + 散文说明**（标签内部一律留空，
模型没有任何可以照抄的内容），解析器再加一道过滤兜底。
正文的过滤刻意比列表项**更窄** —— 正文是文学文本，宁可漏杀不能误杀
（例如 `〈〉` 书名号在中文小说里是合法写法，所以不在正文里过滤）。

## 架构

```
lib/
├── core/        常量 · 错误分类
├── models/      世界书 · 世界线 · 幕节点 · 世界状态 · 词条人物 · 存档槽 · 配置
├── data/        本地存储（防抖写）· 加密存储 · 世界书仓库
├── services/    流式客户端 · 输出解析 · 提示词组装 · 拒答兜底 · 正文排版
│                世界状态 · 编年史 · 会话状态机 · 存档 · 世界书生成 · 更新检查
└── ui/          主题 · 页面 · 组件
```

依赖自上而下单向流动，下层不反向依赖上层。
**UI 层不包含任何具体剧本信息** —— 界面上出现的每个字都来自当前世界书。

三个关键模块：

- **`models/world_line.dart`** —— 一条世界线。自带 `history` / `chronicle` /
  `worldState` 三件套，外加分岔来源（`parentLineId` / `branchedAtChapter`）
  与分岔点之前的状态（`baseState` / `baseChronicle`）。
  一个 `SaveSlot` 含若干条线 —— 这是「互不干扰」的结构基础。
- **`services/game_session.dart`** —— 一局推演的状态与纯逻辑
  （分岔 / 切换 / 重命名 / 删除 / 快照自愈 / reroll / 主宰模式状态一致性），与 UI 完全解耦。
  拆出来是为了让世界线一致性**可以单测**（全量 111 项自动化单测 100% 全绿，全面覆盖世界线分岔、主宰意志注入、正文前缀清洗、状态快照与并发隔离）。
- **`services/world_state_service.dart`** —— 世界状态的解析、合并、校验、截断。
  所有写入口都必须过这一道。

### 核心不变量

> `history` · `chronicle` · `worldState` 三者必须永远处于同一个时间点。

实现方式是 `ChapterNode` 上的**每幕快照**（`chronicleAfter` / `worldStateAfter`）。

只在存档顶层存一份「当前状态」是**分岔不到历史幕**的 —— 顶层那份永远是最新的。
分岔、reroll、编年史压缩三条路径都必须维护这个不变量。

旧存档可能缺快照（世界书自带开篇时，第一幕是在 UI 层直接构造的）。
`GameSession` 在构造时调 `ensureSnapshots()` **自愈**：缺快照的幕取上一幕的快照，
第一幕取空状态 —— 它没跑过模型，状态本来就是空的，对开篇场景是**精确值**。
自愈只在内存里做，等用户下次正常保存时自然写回。

### 提示词三层

| 层 | 是否可改 | 作用 |
|---|---|---|
| 内核层 | 锁定 | 输出格式契约（`<date>` / `<choices>` / `<glossary>` / `<cast>` / `<state>`）、角色约束 |
| 框架层 | 可改，可恢复默认 | 叙事框架、创作定位 |
| 世界层 | 完全自由 | 世界观、玩家身份与目标、关键人物势力地点、文风、规则 —— 全部来自世界书 |

### 模型输出契约

模型每幕必须返回带标签的结构，应用解析后渲染。
**这五个块全部是元数据，读者不该看见** —— 只有正文进阅读区：

```
<date>剧中日期</date>
（正文）

<choices>
第一条可选行动
第二条可选行动
</choices>

<glossary>
词条|解释
</glossary>

<cast>
姓名|身份|立场
</cast>

<state>
时间：此刻的剧中时间
地点：主角此刻所在
事实：条目；条目
关系：姓名|此刻态度；姓名|此刻态度
事件：进行中的事件；事件
</state>
```

缺少 `<choices>` 会被判定为截断，走兜底链路。

解析器是四步流水线（标签定位 → 结构块切分 → 结构化提取 → 正文重建），
对畸形输出尽量宽容。**但不做过度正文清洗** ——
正文里出现的 `名字|身份|立场` 行只要不在结构块内就原样保留。

### 深度思考模式与常驻展示

开启后模型会在正文前先输出 `<think>` 思考链，应用**在流式阶段就把思考与正文分开**：

- **全程常驻展示**：推演进行期间只要存在思考内容，思考面板全程常驻正文上方，用户展开后绝不自动收起或关闭；正文流式输出并在下方同步展示；本幕完成后平滑过渡到章节菜单的思维链查看
- **原生纯净流式拼接**：彻底移除逐字 SSE Chunk 上的过度规范化处理，还原原生流式拼接，彻底消除吞换行、吞空格、单词粘连问题
- **自然段落排版规范化**：思考规范化逻辑智能保留段落之间的单个空行，呈现工整优雅的自然分段；提示词层同步约束朴素中文自然语言排版
- **段落断崖与特征探测**：升级未闭合 `<think>` 截断判定，除检测下一个结构标签外，增加文学小说自然叙事特征与段落断崖探测，严禁将没有 `<body` 标签的文学正文误吞为思考（彻底根治正文变空触发改写重试的问题）

### 重试与残留清理

兜底链路每次重试前会向 UI 统一发送 `restart` 事件 —— **先清屏并清除历史过程提示**，绝不会出现「上一版不合格内容与重写内容混在一起」。章节落定（或降级）后，过程性提示一并彻底作废，只有降级这种终态才留一句话。

### 运行日志与精准脱敏

设置页「调试与日志」与阅读页章节菜单都提供**导出运行日志**，输出到 `Download/nijing/`（或直接走系统分享）。日志是内存中的环形缓冲（最多 2000 条、单条 600 字），默认关闭、需手动开启。内置**双重脱敏防线**：不仅覆盖常见前缀（`sk-`、`gsk_` 等）、Bearer 请求头与 URL Query，更自动对当前配置的真实 API 密钥进行动态精准脱敏，确保排障日志绝对安全。
